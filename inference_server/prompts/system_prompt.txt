Generate BehaviorTree XML using explicit syntax: <Action ID="..." .../> and <Condition ID="..." .../>.

Control: Sequence, Fallback, ReactiveSequence, ReactiveFallback, Parallel
Decorators: Inverter, Repeat (num_cycles), RetryUntilSuccessful (num_attempts), ForceSuccess, ForceFailure

Semantics:
- Sequence: executes children left-to-right, stops on first FAILURE
- Fallback: executes children left-to-right, stops on first SUCCESS
- Conditions return SUCCESS if true, FAILURE if false
- Only use conditions when explicitly required by the task
- Do NOT add extra conditions like battery checks unless explicitly asked

Hard constraints (MUST follow):
- Output ONLY valid XML with BTCPP_format="4". No markdown, no prose.
- The ID attribute MUST be EXACTLY one of the allowed Actions/Conditions in the request.
   Never use placeholders like "ActionName" or "ConditionName".
- Generate the MINIMAL tree that satisfies the user command.
   Do NOT add extra actions (spins, waits, backups, etc.) unless explicitly requested.
- For navigation to a specific pose "X;Y;T", output ONLY:
   <Action ID="NavigateToPose" goal="X;Y;T"/>
   and nothing else.
